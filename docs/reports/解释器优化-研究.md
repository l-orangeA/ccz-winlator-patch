# 研究：能不能"优化解释器"提速？

日期：2026-11-02　范围：纯静态分析 + 已有实测数据，未改动设备。

## 0. 先把"解释器"分成两层

| 层 | 是什么 | 能不能动 |
|---|---|---|
| **壳里的 VM 解释器**（guest x86 代码） | VProtect 用自己的字节码逐条执行解密/反调试逻辑，46 s 就花在这上面 | ❌ 改它＝改游戏＝破解，已排除 |
| **box64**（host 侧把 x86 翻成 ARM64） | 决定"每条 guest 指令要花多少条 ARM 指令" | ✅ 合规可优化，这次研究的就是它 |

## 1. 46 秒到底在干什么（估算）

- 起点：单核 100% 跑 46 s ≈ **1.4×10¹¹ 个 host 周期**
- 按 box64 常见的"每条 guest 指令 10~20 条 host 指令"折算 ≈ **数十亿条 guest 指令**
- 而实际需要处理的数据只有 ~1.4 MB ⇒ 平均**每个字节要跑几千条指令**

这就是"解释器"的成本：不是算法重，是**逐条解释**。所以：
- 想靠"多线程"没用（前面已论证）；
- 想靠"优化 box64"有天花板——只能把"每条 guest 指令的 host 代价"压下来。

## 2. box64 侧还有哪些开关（这版 0.3.0 支持的全表已在二进制里列出）

**已试过并保留**：`DYNAREC_BIGBLOCK=3`、`FORWARD=1024`、`CALLRET=1` → 合计 **2~5%**。

**试过但会破坏反调试**：`SAFEFLAGS=0`、`FASTNAN=1`、`FASTROUND=1` → 游戏不出窗口。

**还没试、值得一试（低风险）**：
| 变量 | 作用 | 预期 |
|---|---|---|
| `BOX64_DYNAREC_WAIT=0` | 不再等其它线程的块，编译即用 | 单线程场景可能 0~3% |
| `BOX64_DYNAREC_ALIGNED_ATOMICS=1` | 原子操作走对齐快路径 | 有原子操作才有效，可能 0% |
| `BOX64_X87_NO80BITS=1` | x87 不模拟 80 位精度 | 只对 FPU 重负载有效 |
| `BOX64_SSE_FLUSHTO0=1` | SSE 异常标志处理简化 | 同上 |

**不要碰**：
- `DYNAREC_FASTPAGE` / `HOTPAGE`：它们也靠 mprotect 管页，**会和我们的软件断点（页保护+TF 单步）抢同一套机制**；
- `BOX64_RDTSC*`：壳有计时类反调试，改它风险高；
- `BOX64_NOSIGSEGV` / `NOSIGILL`：直接破坏我们的异常路径。

## 3. 结构性问题：真正的瓶颈不是"翻译质量"，是"指令条数"

- box64 的 dynarec 已经很成熟，热循环只翻译一次；46 s 里 **翻译开销占比很小**，绝大部分是**执行**。
- 也就是说：把每条指令的 ARM 代价从 15 条压到 12 条（很乐观），整体也就快 20%，即 46 s → ~37 s。
- 想真正翻倍，只能**减少 guest 指令条数**——而那是壳的逻辑，等于脱壳。

### 唯一有量级潜力的合规手段：换更新的 box64
- 这版是 **box64 0.3.0（2024-08 构建，只有 ASIMD）**；上游此后对 ARM64 dynarec 有持续优化。
- 做法：用 Android NDK 交叉编译新 box64 → 替换 imagefs 里的 `/usr/local/bin/box64` → 重新验证反调试兼容性。
- 预期：**5~20%**（不保证），代价是要装 NDK（~1 GB）并重跑全套回归。
- 注意：新版本可能改变异常/单步语义，**必须重新过一遍 tf3_test / stkfault 探针和游戏启动验证**。

## 4. 结论

1. "优化解释器"在合规范围内 = 优化 box64 的翻译质量，**天花板大约 10~20%**（46 s → 37~41 s），不是量级改善。
2. 剩余便宜开关（`WAIT` / `ALIGNED_ATOMICS` / x87 相关）预计 0~5%，可以花 20 分钟 A/B 掉。
3. 想翻倍只能换新 box64（要 NDK + 全量回归），或者脱壳（越界）。
4. 相比之下，"别退出游戏、切后台 3 秒回来"仍然是性价比最高的手段。

## 5. 建议的下一步（需要动设备，等你点头）

按此顺序做 A/B，每次只改一个变量，用 `tools/measure2.py` 计时（±2 s 噪声，只认 >3 s 的差异）：
1. `BOX64_DYNAREC_WAIT=0`
2. `BOX64_DYNAREC_ALIGNED_ATOMICS=1`
3. `BOX64_X87_NO80BITS=1` + `BOX64_SSE_FLUSHTO0=1`
4. （可选）NDK 编译 box64 0.3.6+ 替换验证
